# Audience profiles

Each profile describes a kind of reader: what they already know, so documents can skip it, and what they need explained. Pick the profiles that match a document's readers before writing, and write only what falls outside what they know.

Profiles describe roles, not people. When feedback shows a profile is wrong ("they already know that", "they won't know what this means"), update the profile rather than just the document, so the next project benefits.

Each profile has the same sections: who they are, what they know, what to explain, and what they look for first.

- [Technical operator](technical-operator.md): runs servers and admin consoles for a small organisation.
- [Developer peer](developer-peer.md): builds software and could fork or run the project.
- [AI-fluent professional](ai-fluent-professional.md): uses Claude or ChatGPT daily, but not the terminal.
- [Decision-maker](decision-maker.md): approves or funds adoption; reads the overview only.
- [Reader's agent](readers-agent.md): the Claude Code, Codex or Cowork session a reader points at the repo.
